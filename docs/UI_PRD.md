# devctl 悬浮窗 — 需求文档 (PRD)

版本: 0.1 | 状态: 评审中 | 负责人: devctl 团队

## 1. 背景与目标

devctl 已具备 agent (root daemon, TCP:5556 TLS) 与 DevUI 渲染基座 (SurfaceControl 反射,
无 APK 直绘屏幕)。当前悬浮窗为 v0.5 基础版 (悬浮球 + 二级信息面板)。

本次迭代目标: **把悬浮窗升级为 GG 修改器风格**, 提供设备连接状态的可视化面板,
让用户无需打开电脑即可在设备上查看 devctl 的连接情况。

## 2. 用户故事 (User Stories)

| 编号 | 故事 | 优先级 |
|---|---|---|
| US-1 | 作为设备持有者, 我想看到一个可拖动的悬浮球, 以便随时点开连接面板 | P0 |
| US-2 | 作为设备持有者, 我想点击悬浮球打开全屏覆盖面板, 以便看清连接详情 | P0 |
| US-3 | 作为设备持有者, 我想在面板上看到本机被几个设备连接 (客户端列表), 以便知道谁在控制我的设备 | P0 |
| US-4 | 作为设备持有者, 我想看到悬浮窗自身与 agent 的通信状态, 以便确认面板数据是否新鲜 | P1 |
| US-5 | 作为开发者, 我想通过命令行/截图自动验证 UI 渲染, 以便无需人工盯屏 | P1 |

## 3. 功能需求 (Functional Requirements)

### FR-1 悬浮球 (继承 v0.5)
- 圆角方形/圆形外观, GG 深色主题
- 可拖动 (TouchInput), 点击 (tap) 打开面板
- 位置初始: 屏幕右侧 1/3 处

### FR-2 全屏覆盖面板
- 尺寸 = 屏幕 (wm size), 位置 (0,0), 顶层 z
- 深色背景 (#0F1117), 标题栏 (#161A23 高 96px, GG 蓝强调线)
- 底部两个按钮: 刷新 / 关闭

### FR-3 连接信息区 (面板中部)
- 本机信息: 型号 / Android 版本 / SDK
- 被连接状态: 活跃客户端数量 + 客户端列表 (名字/地址/最后命令)
- 自身通信状态: agent 存活标记 + dash.json 数据时间戳

### FR-4 agent 侧数据供给
- 新增方法 `peers()`: 返回当前活跃连接列表 JSON
- 状态文件 `/data/local/devctl/dash.json`: agent 刷新的汇总 (连接数/客户端/时间戳)
- UI 进程读取 dash.json 渲染 (与 agent 解耦, UI 崩溃不影响 agent)

## 4. 非功能需求 (NFR)

| 项 | 要求 |
|---|---|
| 稳定性 | UI 进程崩溃不影响 agent; agent 崩溃 10s 自动拉起 |
| 性能 | 面板刷新 ≤ 500ms; 触摸响应 ≤ 100ms |
| 安全 | UI 进程仅读 dash.json / 自身层操作; 绝不操作他人进程 |
| 兼容 | Android 12-16, 屏幕 ≥ 1080p, 字库点阵渲染 |

## 5. 验收标准

- US-1/2: 悬浮球可拖, 点击全屏面板出现, 截图可验证
- US-3: 面板显示真实连接数 (用 2 个 client 连接时数字 = 2)
- US-4: dash.json 时间戳随 agent 刷新更新, 面板显示"正常"
- US-5: `tests/ui_test.sh` 一键跑: 构建→部署→截图→断言→报告

## 6. 范围界定 (Out of Scope)

- 不做 UI 远控 (agent 反向控制 UI 按钮交互)
- 不做多语言 (仅中文+ASCII 点阵字库)
- 不做 Mac/Linux 版本 agent 的悬浮窗 (仅 Android)
